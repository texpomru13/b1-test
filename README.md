# Тестовое задание по поиску ответов в документах

FastAPI-сервис принимает PDF или DOCX до 100 страниц и отвечает на вопросы по выбранному документу. Вместе с ответом он возвращает дословные цитаты, страницы и координаты текста. Если подтверждения недостаточно, ответ содержит `found=false` и пустой список цитат. Каждый вопрос независим.

## Запустить и проверить

В корне репозитория выполните две команды. Для первой нужен Docker с Compose v2, для второй — также `curl` и `jq`.

```sh
./run --build
sh eval/demo.sh
```

Первая команда собирает сервис, подбирает профиль по доступной памяти и ждёт готовности API. При первом запуске нужны интернет и место для образов и весов. Базовый профиль `balanced` использует Giga-Embeddings 480M, bge-reranker-v2-m3 и Qwen 3.5 9B через Ollama. Ollama может работать на хосте macOS или в контейнере. Ключи API для локального запуска не нужны. На Windows запуск доступен через `.\run.ps1 --build` с настроенными WSL2 и Docker Desktop. Демо запускается из shell в WSL.

Вторая команда загружает два договора, ждёт индексации и печатает вопросы, ответы и страницы. Она также проверяет перефразирование, диагностику и изоляцию документов. JSON каждого запроса сохраняется в `eval/reports/demo/<время UTC>/`. Интерактивная документация работающего API — [Swagger UI](http://127.0.0.1:8000/docs).

### Что показывает демо

| Вопрос к договору аренды | Ответ API |
|---|---|
| Какова ежемесячная плата по п. 3.1.1 и включает ли она НДС? | **158 400 рублей, включая НДС**. Обе цитаты на стр. 5, раздел 3.1.1. [Ответ и точные цитаты](eval/reports/submission/demo/07_exact.json) |
| Какой обеспечительный платёж должен внести арендатор? | `found=false`, `citations=[]`. [Ответ об отсутствии сведений](eval/reports/submission/demo/09_no_answer.json) |
| Какая неустойка предусмотрена п. 5.1? | 0,1% от просроченной суммы за каждый день. При `debug=true` видно, что каждая поисковая ветвь вернула 60 фрагментов, реранкер оценил 60 кандидатов, в контекст вошли 8, для ответа использован 1. [Ответ с диагностикой](eval/reports/submission/demo/10_debug.json) |

Если сервис не поднялся, `./run doctor --json` покажет выбранный профиль и ограничения окружения, `./run logs` — журналы. `./run stop` останавливает сервисы с сохранением документов и индекса.

## API

| Метод и путь | Запрос и результат |
|---|---|
| `POST /api/v1/documents` | Multipart с `file`, необязательными `title` и заголовком `Idempotency-Key`. HTTP 202 возвращает `doc_id`, `job_id`, `status`, `status_url` и `document_url`. [Пример загрузки](eval/reports/submission/demo/01_upload_a.json) |
| `GET /api/v1/jobs/{job_id}` | Состояние, этап, прогресс обработки, номер попытки и ошибка. После `succeeded` документ доступен для вопросов. [Пример результата задачи](eval/reports/submission/demo/03_poll_a_final.json) |
| `GET /api/v1/documents` | Постраничный список `items` и `next_cursor`. Параметры `limit` (1–100) и `cursor` необязательны. |
| `POST /api/v1/documents/{doc_id}/questions` | JSON с `question` и необязательным `debug`. HTTP 200 возвращает `answer`, `found` и `citations`. |

Для загруженного договора скопируйте строку `DOC_ID=…` из вывода демо в shell. Эти запросы соответствуют первым двум строкам таблицы.

```sh
QUESTIONS="http://127.0.0.1:8000/api/v1/documents/$DOC_ID/questions"
curl -fsS "$QUESTIONS" -H 'Content-Type: application/json' \
  -d '{"question":"Какой размер постоянной части арендной платы установлен п. 3.1.1 договора аренды нежилого помещения и включает ли он НДС?"}'
curl -fsS "$QUESTIONS" -H 'Content-Type: application/json' \
  -d '{"question":"Какой обеспечительный (гарантийный) платёж вносит арендатор по договору аренды нежилого помещения?"}'
```

Ссылка `[n]` в ответе указывает на `citations[].id`. `text` — точная выдержка, `page` и `page_to` — физические страницы с единицы, `section` — раздел или `null`. Смещения `char_start` и `char_end` обозначают начало и конец в каноническом тексте, правая граница исключается. Страницы DOCX соответствуют PDF после конвертации. Исходные страницы для проверки доступны через `GET /api/v1/documents/{doc_id}/normalized`.

`debug=true` добавляет размеры выдачи, `context_chunk_ids` и `cited_chunk_ids`. Для раздельных счётчиков ветвей сервис дополнительно запрашивает Qdrant. Если измерение недоступно, счётчики равны `null` и в ответе есть предупреждение.

Ошибки имеют форму `{"error":{"code":"…","message":"…","retryable":false,"request_id":"…"}}`. Неизвестный документ даёт 404, ожидающий индексации — 409, слишком большой файл — 413, неподдерживаемый формат — 415. При временной недоступности зависимости сервис возвращает 503. Полные схемы, ограничения и коды ответов доступны в Swagger UI.

## Как проходит запрос

1. **Загрузка.** FastAPI сохраняет файл и регистрирует задачу в Redis. Диспетчер передаёт её в Celery через брокер Redis и восстанавливает незавершённые задачи после сбоя. [Приём файла](app/api/documents.py) · [Фоновые задачи](app/jobs)
2. **Индексация.** Воркер извлекает текст из PDF. Для DOCX он сначала получает постраничный PDF через LibreOffice. LangChain делит текст с перекрытием. Сервис моделей строит плотные векторы через LangChain `Embeddings`, FastEmbed строит разреженные BM25-векторы. Одна точка Qdrant хранит оба вектора, текст, идентификатор и название документа, номер фрагмента, страницы, раздел и символьные координаты. Redis открывает индекс для поиска после записи всех фрагментов. [Разбиение](app/ingestion/chunker.py) · [Модели](services/local-models/app_lm/server.py) · [Публикация индекса](app/jobs/indexer.py)
3. **Поиск.** Все документы находятся в одной коллекции. Обе поисковые ветви фильтруются по идентификаторам документа и опубликованной попытки индексации. Для этих полей настроены payload-индексы. Один запрос Qdrant объединяет выдачу dense и BM25. Обязательный реранкер оценивает общий список, верхние фрагменты попадают в контекст. [Гибридный поиск](app/retrieval/search.py)
4. **Ответ.** Чат-модель LangChain формирует утверждения с доказательствами. Сервер проверяет цитаты, числа и координаты. Отдельный вызов модели проверяет смысловую поддержку утверждений и полноту ответа. Для распознанного нумерованного перечня проверяются и подпункт, и применимая к нему вводная фраза. Pydantic валидирует результат. Временные ошибки LLM и Qdrant обрабатываются с ограниченным числом повторов. [Обработка вопроса](app/qa/workflow.py) · [Схема ответа](app/schemas/qa.py)

## Настройки

Параметры задаются через окружение или `.env`. Отдельный сервис держит веса энкодера и реранкера в памяти и обслуживает и API, и воркер индексации. [Полный пример конфигурации](.env.example)

| Параметр | По умолчанию и назначение |
|---|---|
| `FUSION_METHOD` | `rrf`, также доступен `dbsf` |
| `DENSE_TOP_K`, `SPARSE_TOP_K` | По 60 кандидатов от каждой поисковой ветви |
| `RERANKER_MODEL`, `RERANK_INPUT_K`, `CONTEXT_TOP_K` | Для `balanced` — bge-reranker-v2-m3, до 60 кандидатов на входе и 8 фрагментов в контексте |
| `CHUNK_TOKENS`, `CHUNK_OVERLAP_TOKENS` | 450 токенов на фрагмент, перекрытие 64 токена |
| `QUALITY_PROFILE`, `EMBEDDING_MODEL`, `LLM_PROVIDER`, `LLM_MODEL` | Профиль запуска и выбор моделей. Облачный провайдер включается явно и требует своего API-ключа |

Например, `DENSE_TOP_K=40 SPARSE_TOP_K=30 RERANK_INPUT_K=50 CONTEXT_TOP_K=3 ./run` меняет глубину поиска и реранжирования. Порт задаётся через `./run --port 8001`, адрес для демо — `sh eval/demo.sh http://127.0.0.1:8001`. Смена энкодера, параметров BM25 или размера фрагмента может потребовать переиндексации документов.

## Проверка качества и ограничения

Для модульных тестов достаточно `uv run --frozen pytest tests/unit -q`. Интеграционные тесты запускаются командой `RUN_STACK_TESTS=1 uv run --frozen pytest tests/integration -q -ra`. Им нужны Docker и работающий API. Для проверок с реальными моделями подготовьте окружение командой `uv sync --frozen --project services/local-models` и локальный кэш весов. `B1_TEST_API_URL` задаёт адрес API, `-ra` показывает причины пропусков. [Инструкция для оценки на корпусе](eval/README.md)

Проверка охватила **150 запросов по 14 договорам** на локальном профиле `balanced`.

| Показатель | Результат |
|---|---:|
| Сервис дал ответ при наличии сведений в договоре | 80/93 |
| Ответ содержит все ожидаемые факты по оценке локальной модели-судьи | 50/93 |
| Сервис отказал при отсутствии сведений | 40/40 |
| Сервис отказал на вопрос к чужому договору | 17/17 |

Все 153 цитаты совпали с текстом и номерами страниц исходных документов. [Протокол и границы измерения](AUDIT.md)

Для скана без текстового слоя возвращается `OCR_REQUIRED`. Перед production нужны права доступа к документам, изоляция клиентов, резервное копирование Redis, Qdrant и файлов, политика хранения исходников и мониторинг очереди и ошибок. Для сканов понадобится OCR, для сложных таблиц и договорных исключений — отдельная проверка распознавания и полноты ответов на независимой разметке.
