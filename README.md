# Вопросы по документам

Backend на FastAPI принимает PDF или DOCX до 100 страниц, индексирует его в фоне и отвечает на вопросы по выбранному документу. К каждому утверждению сервис прикладывает цитату, номер страницы и координаты текста. Если доказательств недостаточно, API возвращает `found=false`. Каждый вопрос обрабатывается независимо.

## Запуск

Нужен Docker с Compose v2. Запустите из корня репозитория. Флаг `--build` собирает текущие исходники и подходит также для обновления существующей установки.

```sh
./run --build
curl -fsS http://127.0.0.1:8000/health/ready
```

При первом запуске скачиваются образы и веса моделей, поэтому нужны интернет, место на диске и время. Базовый профиль `balanced` использует Giga-Embeddings-instruct-480M, bge-reranker-v2-m3 и Qwen 3.5 9B. Launcher учитывает доступную память. На Mac можно использовать запущенный Ollama на хосте. В контейнерном варианте Ollama входит в Compose. Локальному профилю ключ API не нужен. На Windows с WSL2 и интеграцией Docker Desktop запустите `.\run.ps1`.

| Команда | Назначение |
|---|---|
| `./run doctor --json` | Получить результат проверки окружения и выбранный профиль |
| `./run --dry-run` | Посмотреть разрешённую конфигурацию |
| `./run --quality balanced --strict-profile --port 8001` | Задать профиль и порт, потребовать точного выбора профиля |
| `./run --build` | Пересобрать образы после изменения исходников |
| `./run status`, `./run logs` | Состояние контейнеров и их журналы |
| `./run stop`, `./run down` | Остановить сервисы или убрать контейнеры с сохранением томов |

Для второй независимой установки задайте `B1_PROJECT` и свободный порт. Для всех следующих команд указывайте то же имя проекта. Данные сохраняются в томах Compose. Swagger UI доступен по адресу `/docs`, схема OpenAPI — по `/openapi.json`.

## От загрузки до ответа

Пример для POSIX shell использует `curl` и `jq`. Образец договора входит в репозиторий.

```sh
API=http://127.0.0.1:8000
FILE=test_documents/04_Аренда_производственного_помещения.pdf
upload=$(curl -fsS "$API/api/v1/documents" -F "file=@$FILE;type=application/pdf")
doc=$(printf '%s' "$upload" | jq -er .doc_id)
job=$(printf '%s' "$upload" | jq -er .status_url)

while :; do
  status=$(curl -fsS "$API$job" | jq -er .status) || exit 1
  case "$status" in
    succeeded) break ;;
    failed|cleanup_pending) curl -sS "$API$job"; exit 1 ;;
  esac
  sleep 2
done

curl -fsS "$API/api/v1/documents"
curl -fsS "$API/api/v1/documents/$doc/questions" -H 'Content-Type: application/json' \
  -d '{"question":"Какой размер постоянной части арендной платы установлен п. 3.1.1 договора аренды нежилого помещения и включает ли он НДС?","debug":true}'
curl -fsS "$API/api/v1/documents/$doc/questions" -H 'Content-Type: application/json' \
  -d '{"question":"Какой обеспечительный (гарантийный) платёж вносит арендатор по договору аренды нежилого помещения?"}'
```

На этом договоре загрузка вернула 202, а опубликованный индекс содержит 90 фрагментов. [Ответ загрузки](eval/reports/acceptance/2026-11-20/demo/01_upload_a.json) · [Результат задачи](eval/reports/acceptance/2026-11-20/demo/03_poll_a_final.json)

При проверке по п. 3.1.1 сервис вернул **158 400 рублей ежемесячно, включая НДС**. Обе цитаты находятся на странице 5. Первая содержит сумму с расшифровкой прописью, вторая подтверждает включение НДС. [Полный JSON ответа](eval/reports/acceptance/2026-11-20/demo/07_exact.json)

На вопрос про обеспечительный платёж ответ был таким. [Сохранённый ответ API](eval/reports/acceptance/2026-11-20/demo/09_no_answer.json)

```json
{"answer":"В документе не найдено достаточно сведений для ответа на этот вопрос.","found":false,"citations":[]}
```

Весь сценарий можно повторить командой `sh eval/demo.sh "$API"`. Он проверяет два PDF, точный вопрос, перефразирование, отказ, диагностику и запрос к чужому документу. Ответы сохраняются в `eval/reports/demo/`. Значение `B1_DEMO_DIR` меняет каталог вывода.

## Контракты API

| Метод и путь | Вход | Результат |
|---|---|---|
| `POST /api/v1/documents` | Multipart `file`, необязательные `title` и заголовок `Idempotency-Key` | 202, поля `doc_id`, `job_id`, `status`, `status_url`, `document_url`. Заголовок `Location` указывает на задачу |
| `GET /api/v1/jobs/{job_id}` | Идентификатор из ответа загрузки | Состояние, текущий этап, номер попытки, прогресс, время и ошибка. После `succeeded` можно задавать вопросы |
| `GET /api/v1/documents` | Необязательные `limit` (1–100) и `cursor` | `items` с идентификаторами, заголовками, состоянием и признаком готовности, а также `next_cursor` |
| `POST /api/v1/documents/{doc_id}/questions` | JSON с непустым `question` и необязательным `debug` | 200, поля `answer`, `found`, `citations`. При `debug=true` добавляется `diagnostics` |
| `GET /api/v1/documents/{doc_id}` | Идентификатор документа | Карточка с состоянием, именем файла, количеством страниц и фрагментов |
| `GET /api/v1/documents/{doc_id}/normalized` | Идентификатор документа | PDF, по которому можно сверить страницы и цитаты |
| `GET /health/live`, `GET /health/ready` | — | Доступность процесса и состояние зависимостей соответственно |

В цитате `id` соответствует ссылке `[n]` в ответе. `text` — дословный фрагмент канонического текста, `page` и `page_to` — физические страницы с единицы, `section` — распознанный раздел или `null`. Поля `chunk_id`, `char_start` и `char_end` позволяют проверить источник. Смещения измеряются в символах, правая граница исключается. Страницы DOCX соответствуют PDF, который сформировал сервер.

Диагностика показывает реальные размеры плотной и разреженной выдачи, объединённого списка, списка после реранкера и контекста. `context_chunk_ids` перечисляет фрагменты, переданные модели, `cited_chunk_ids` — фрагменты, которые подтверждают итоговый ответ. Qdrant не раскрывает раздельные счётчики в ответе fusion. В режиме диагностики сервис повторяет ветви для измерения. Если измерение недоступно, возвращаются `null` и предупреждение.

Ошибки имеют форму `{"error":{"code":"…","message":"…","retryable":false,"request_id":"…"}}`. Неизвестный документ даёт 404, вопрос до окончания индексации или конфликт ключа загрузки — 409. Превышение лимита файла даёт 413, неподдерживаемый формат — 415, лишние поля истории — 422. При перегрузке возвращается 429, при ошибке формата ответа модели — 502, при недоступности зависимости — 503, при истечении общего срока — 504. Отказ из-за недостатка сведений имеет статус 200.

## Как работает сервис

1. **Приём и индексация.** FastAPI сохраняет файл, регистрирует задачу в Redis и возвращает 202. Диспетчер передаёт её в Celery с брокером Redis. Воркер извлекает текст из PDF, DOCX предварительно преобразует в PDF через LibreOffice. Для скана без текстового слоя предусмотрена ошибка `OCR_REQUIRED`.
2. **Фрагменты и векторы.** LangChain `RecursiveCharacterTextSplitter` делит текст с перекрытием. Для каждого фрагмента сохраняются страницы, раздел и координаты. Реализация LangChain `Embeddings` в сервисе `local-models` строит нормализованный dense-вектор. Для вопроса применяется инструкция поискового энкодера. FastEmbed строит разреженный BM25-вектор.
3. **Публикация.** В общей коллекции Qdrant одна точка содержит оба именованных вектора и payload с `doc_id`, `doc_title`, `chunk_index`, `page_from`, `page_to`, `section`, `text`, `char_start`, `char_end`. Поисковые поля имеют payload-индексы. После записи и проверки всех фрагментов Redis фиксирует опубликованную попытку. Это защищает от выдачи незавершённого индекса при падении воркера. Отдельной SQL-базы нет.
4. **Поиск.** Плотная и BM25-ветви выполняются с фильтром документа и версии индекса. Один запрос Qdrant объединяет обе выдачи методом RRF или DBSF. Отдельная модель реранкера оценивает объединённых кандидатов. В контекст попадают верхние фрагменты, которые укладываются в бюджет токенов.
5. **Ответ.** Чат-модель LangChain формирует утверждения с цитатами. Сервер находит цитаты в тексте, восстанавливает смещения и страницы, проверяет числа. Отдельный вызов модели проверяет, подтверждены ли утверждения и отвечают ли они на вопрос. При ошибке допускается ограниченная попытка исправления. Pydantic валидирует результат. Состояние конкретного вопроса живёт только во время HTTP-запроса.

Код обработки вопроса находится в [app/qa/workflow.py](app/qa/workflow.py), поиск — в [app/retrieval/search.py](app/retrieval/search.py), индексация — в [app/jobs](app/jobs). Сервис моделей держит веса в отдельном процессе, поэтому воркеры API обходятся без PyTorch. Для временных ошибок LLM и Qdrant действуют ограниченные повторы с задержкой. После сбоя индексации диспетчер проверяет состояние задачи и завершает публикацию, повторяет попытку или очищает частичную запись.

## Настройки

Задайте значения в окружении или в `.env` в корне проекта. Таблица охватывает настройки, от которых зависит выполнение задания.

| Переменные | Что меняют |
|---|---|
| `FUSION_METHOD` | `rrf` (по умолчанию) или `dbsf` |
| `DENSE_TOP_K`, `SPARSE_TOP_K` | Кандидаты до объединения, по умолчанию по 60 |
| `RERANKER_MODEL`, `RERANK_INPUT_K`, `CONTEXT_TOP_K` | Модель, максимум кандидатов на входе и фрагментов на выходе, по умолчанию 60 и 8 |
| `CHUNK_TOKENS`, `CHUNK_OVERLAP_TOKENS`, `CONTEXT_BUDGET_TOKENS` | Размер фрагмента, перекрытие и бюджет контекста, по умолчанию 450, 64 и 6000 |
| `QUALITY_PROFILE`, `EMBEDDING_MODEL`, `LLM_PROVIDER`, `LLM_MODEL` | Выбор профиля, энкодера и языковой модели для launcher |
| `REDIS_URL`, `CELERY_BROKER_URL`, `QDRANT_URL`, `QDRANT_API_KEY`, `LOCAL_MODELS_URL` | Адреса и учётные данные зависимостей |
| `LLM_MAX_ATTEMPTS`, `QDRANT_MAX_ATTEMPTS`, `JOB_MAX_ATTEMPTS`, `QA_DEADLINE_S`, `INDEXING_SOFT_TIME_LIMIT_S` | Лимиты повторов и времени |
| `MAX_FILE_MB`, `MAX_PAGES`, `MAX_QUESTION_CHARS`, `MAX_CONCURRENT_QA` | По умолчанию 25 МиБ, 100 страниц, 4000 символов, один одновременный вопрос на процесс API |

Например, `FUSION_METHOD=dbsf DENSE_TOP_K=40 SPARSE_TOP_K=30 RERANK_INPUT_K=50 CONTEXT_TOP_K=3 ./run` меняет весь отбор кандидатов. При старте проверяется соотношение `CONTEXT_TOP_K ≤ RERANK_INPUT_K ≤ DENSE_TOP_K + SPARSE_TOP_K`. Изменение энкодера, параметров BM25 или разбиения может потребовать новой коллекции и переиндексации. Исходные данные существующей коллекции сохраняются.

Дополнительные профили — `low-memory`, `quality-compact`, `quality`. Облачная модель включается явным выбором провайдера и модели с соответствующим API-ключом. Для запуска без launcher доступен `docker compose up -d --build`. При прямом вызове Compose свойства выбранных моделей задаются через `B1_*`, включая закреплённые ревизии. Полный перечень параметров приведён в [.env.example](.env.example).

## Проверка и ограничения

```sh
uv sync --frozen
uv run --frozen ruff check app tests
uv run --frozen mypy
uv run --frozen pytest tests/unit -q
RUN_STACK_TESTS=1 uv run --frozen pytest tests/integration -q -ra
```

Для двух модулей, обращающихся к запущенному API, можно задать `B1_TEST_API_URL`. Остальные интеграционные тесты используют временные Redis и Qdrant, часть — отдельное окружение `services/local-models` и предварительно скачанные веса. Причину каждого пропуска выводит `-ra`.

На эталонном наборе сервис дал 79 ответов из 93 вопросов с ответом. Правильные отказы выросли с 39/40 до 40/40, полные ответы по оценке локальной модели-судьи — с 45/93 до 49/93. Все 17 проб на чужом документе дали отказ. Итог включает применение последней проверки числовых утверждений ко всем 150 записанным ответам и отдельный живой контроль изменившегося случая. Вопросы составляла модель, часть примеров holdout изучалась при диагностике. [Проверка по ТЗ и подробное сравнение](AUDIT.md) · [Исходные результаты](eval/reports/SUMMARY.md) · [Воспроизведение оценки](eval/README.md)

Перед использованием в production нужны авторизация и права на документы, изоляция арендаторов, согласованные резервные копии Redis, Qdrant и файлов, политика хранения исходников и мониторинг очереди, ошибок и задержек. В Redis находятся состояние задач и указатели опубликованных версий. Для сканов потребуется OCR, для таблиц со сложной вёрсткой — проверка извлечения на представительных образцах. Качество ответов и достаточность доказательств стоит оценивать на независимой разметке специалистов предметной области.
