## Выборка

В повторную проверку вошли все 15 положительных вопросов, которые остались без полного ответа в серии из 67 запросов. Для контроля из 51 полного ответа той же серии выбраны 16 без возвращения. Размер контроля равен 30% с округлением вверх (31,4%). Исправленный отказ о максимальной мощности был отдельной проверкой отсутствия сведений. Генератор CPython 3.12 сделал один выбор из отсортированного списка с сохранённым 256-битным начальным значением. Выборка закреплена коммитом `8c8b9c9` до доработок. [Идентификаторы вопросов, выборка и хеши исходных решений](plan.json) · [Исходная оценка](../completeness/README.md)

В работе над исправлениями использованы проблемные вопросы и их выдержки. Итоговые ответы получаются новым запросом через публичный HTTP API для каждого идентификатора из плана. Экспорты индексов, исходные PDF и эталоны должны совпадать с данными исходной серии. Полный ответ должен передать все обязательные факты и условия. Каждое дополнительное утверждение сверяется с приложенной к нему цитатой и областью действия нормы.

## Воспроизведение

Для каждой из четырёх групп в рабочем каталоге с `corpus.json`, `index/` и `gold.jsonl` выполните `eval/run_qa.py --run resolution` с аргументом `--case` и идентификаторами группы из плана. Скрипт `eval/completeness_review.py --study resolution prepare` подготавливает лист для оценки каждого утверждения. Подкоманда `score` связывает оценки с ответами и формирует архив. Команды используют тот же формат рабочих каталогов, что при проверке полноты. [Подготовка и разметка серии](../completeness/README.md#сверка-полученных-ответов)

Чтобы воспроизвести оценку по сохранённым ответам без работающего сервиса, выполните из корня репозитория:

```bash
uv run --offline --frozen python eval/completeness_review.py --study resolution summarize
```
