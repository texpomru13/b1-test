# Проверка полноты ответов

План содержит 67 повторных запросов. В приёмке на 27 документах у 135 вопросов был ответ в источнике. По строгой сверке 99 ответов были полными и 36 неполными. В повторную серию включены все 36 неполных и 30 случайно выбранных полных ответов. Ещё один запрос, `contract-04-08`, проверяет ложный ответ о максимальной мощности. В исходном документе задан только нижний предел. [Вопросы, исходные статусы и группы](plan.json)

Для выборки использованы оценки текста Codex. По офертам использована дополнительная сверка `crosscheck-claims.json`. Источники материалов, SHA-256 и ревизия приложения указаны в плане. Множество из 99 идентификаторов отсортировано по возрастанию. Одно 256-битное значение получено через `secrets.token_hex(32)`. Генератор CPython 3.12 с этим начальным значением один раз выбирает 30 элементов без возвращения. [Исходное значение](seed.txt) · [Реализация](../../completeness.py)

Для побайтового сравнения файлов плана и проверки состава вопросов выполните из корня репозитория `uv run --offline --frozen python eval/completeness.py check-plan`. Для воспроизведения HTTP-серии поле `requests[].series` указывает рабочий каталог группы, `requests[].req_id` — идентификаторы для аргумента `--case` в `eval/run_qa.py`. Один вопрос направляется указанному документу. Изоляционные запросы в этот план не входят. Итоги рассчитываются отдельно для исправлений, случайной контрольной выборки и ложного ответа.
