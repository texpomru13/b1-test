# Проверка полноты ответов

Из **36** положительных вопросов, на которые сервис прежде ответил неполно или отказом, **21 получил полный ответ**. Все **30 из 30** случайно выбранных ранее полных ответов сохранили полноту. На тех же 66 вопросах доля полных ответов выросла с **30/66 (45,5%) до 51/66 (77,3%)**, на **31,8 процентного пункта**. Выборка намеренно включает все прежние ошибки. По Европейской конвенции при полной приёмке были корректны **3/6** положительных ответов. В повтор вошли три отказа и два полных ответа. На тех же пяти вопросах результат вырос **с 2/5 до 5/5**. Сервис указал возраст кандидата и момент его определения, ограничение запроса консультативного заключения конкретным делом, обоих адресатов и обязательность публикации. Шестой вопрос был отвечен правильно при полной приёмке. [Каждый вопрос по Конвенции, цитаты и страницы](series/published-six/ECHR.md)

**В пересчёте на все 135 положительных вопросов** исходная полнота составляла 99/135 (73,3%). По выборке оценка после исправлений составляет **120/135 (88,9%)**, рост на **15,6 п. п.** Из 99 прежних успехов повторены 30. Для 69 остальных результат на этой сборке неизвестен. Номинальный 95-процентный интервал по случайному отбору составляет **111–120 полных ответов (82,2–88,9%)**. Он предполагает, что проверенные контроли представляют все 99 успехов. Четыре контрольных вопроса были видны при отладке. Содержательную оценку выполнил Codex. [Отбор и исходные оценки](plan.json)

### Изменения по типу исходной ошибки

Из **26** содержательных ответов с пропуском, ошибкой или неподходящей ссылкой **17 стали полными**, девять остались неполными. Например, по кран-балке сервис дал 3 т из пункта об арендной плате, а в ответе о пене указал исключение при неисполнении поставщиком своих обязательств. Из **10** исходных ложных отказов **четыре стали полными** (три по Конвенции и один о сроках денонсации), три дали частичный ответ, два снова завершились отказом и один вернул HTTP 502. Отдельный, 67-й, запрос касался максимальной электрической мощности помещения. При наличии только минимума «не менее 50 кВт» сервис теперь корректно вернул `found=false` без цитат. По всей серии 66/67 запросов вернули ответ по схеме HTTP 200. Проверена 151 цитата. Во всех случаях совпали документ, текст, страницы и координаты. В самих ответах переданы 125 из 140 обязательных фактов и условий. Смысловая сверка отдельно проверяла, подтверждает ли каждая приложенная цитата конкретное утверждение. ## Состав выборки и воспроизведение

За основу взята приёмка на 27 документах. План фиксирует формулировку каждого запроса, его документ, исходный результат и принадлежность к выборке. Вопрос о максимальной мощности имеет идентификатор `contract-04-08`. [Вопросы, исходные статусы и группы](plan.json)

Для выборки использованы оценки текста Codex. По офертам использована дополнительная сверка `crosscheck-claims.json`. Источники материалов, SHA-256 и ревизия приложения указаны в плане. Множество из 99 идентификаторов отсортировано по возрастанию. Одно 256-битное значение получено через `secrets.token_hex(32)`. Генератор CPython 3.12 с этим начальным значением один раз выбирает 30 элементов без возвращения. [Исходное значение](seed.txt) · [Реализация](../../completeness.py)

Для побайтового сравнения файлов плана и проверки состава вопросов выполните из корня репозитория `uv run --offline --frozen python eval/completeness.py check-plan`. Для воспроизведения HTTP-серии поле `requests[].series` указывает рабочий каталог группы, `requests[].req_id` — идентификаторы для аргумента `--case` в `eval/run_qa.py`. Один вопрос направляется указанному документу. Изоляционные запросы в этот план не входят. Итоги рассчитываются отдельно для исправлений, случайной контрольной выборки и ложного ответа.

## Что изменилось в сервисе

Поиск связывает статью с её заголовком и протоколом, строку цены с единицей измерения в шапке таблицы, а срок с определением дня в договоре. Для разрыва внутри статьи он запрашивает соседний фрагмент того же опубликованного индекса. При формировании ответа сервис сверяет направление ограничения, применимость пункта и существенные оговорки, включая дату отсчёта и исключения. Когда первый ответ модели оказывается неполным или модель отказывается, следующая попытка может выбрать дословные положения. Сервер проверяет их по документу, а модель проверяет, отвечают ли они на поставленный вопрос. [Разбор 36 неполных ответов и ложного максимума](diagnosis.md) · [Поиск](../../../app/retrieval/search.py) · [Обработка ответа](../../../app/qa/workflow.py)

Состав выборки и исходные оценки зафиксированы до доработок. При отладке сохранили семь пробных HTTP-ответов, среди них четыре контрольных вопроса и три прежних отказа по Конвенции. Эти три отказа также проверяли на сохранённом контексте при разработке. Поэтому итоговая серия измеряет, как приложение справляется с известными проблемами и сохраняет ответы на случайной выборке. Ответы для отчёта получены заново на одной сборке. Файлы PDF, индексы, идентификаторы документов и эталоны сверяются с исходными манифестами.

## Сверка полученных ответов

Для каждой группы подставьте её ключ из плана, каталог с `corpus.json`, `gold.jsonl`, `index/` и имя HTTP-серии. Запуск `prepare` читает готовые ответы, проверяет соответствие вопроса, PDF и индекса, затем создаёт два файла. В `review-input.json` доступны формулировки вопросов, ответы, цитаты с координатами, эталонные факты, исключения и полный текст того же документа. В `claim-review.json` заполняются решения. [Скрипт сверки](../../completeness_review.py)

```bash
group=contracts-six
work="$(pwd)/eval/work/delivery-$group"
if [ "$group" = numbered ]; then work="$(pwd)/eval/work/delivery-catalog"; fi
run=completeness
out="$work/runs/$run/review"
uv run --offline --frozen python eval/completeness_review.py prepare \
  --series "$group" --work "$work" --run "$run" --out "$out"
```

Укажите имя оценщика в `reviewer` и тип в `reviewer_type` (`human` или `model`). В `required_covered` отметьте каждый обязательный факт и условие в том же порядке. Проверьте в цитатах объект, стороны, единицы, сумму, период и исключения. Для каждого фрагмента ответа в `claims` оцените все его утверждения, включая дополнительные. Выберите `supported`, `unsupported`, `wrong_scope`, `contradiction` или `irrelevant`. Для ошибочного фрагмента укажите основание в `reason` и существенность в `critical`. В каждом незачтённом случае опишите конкретный пропуск, подмену или отказ в `assessment`.

Успех положительного вопроса требует валидного ответа, полного покрытия, корректных утверждений и точных цитат. Отказ на положительный вопрос получает ноль покрытия. Для вопроса о максимальной мощности проверяется `found=false` в валидном ответе. Метрики по трём группам плана выводятся раздельно. Результаты контрольной выборки описывают 30 проверенных примеров.

```bash
uv run --offline --frozen python eval/completeness_review.py score \
  --series "$group" --work "$work" --run "$run" --out "$out" \
  --archive "eval/reports/completeness/series/$group"
uv run --offline --frozen python eval/completeness_review.py summarize \
  --root eval/reports/completeness/series \
  --output eval/reports/completeness/result.json
```

Последняя команда требует архивы всех четырёх серий. Она проверяет SHA-256 входов, пересчитывает все 67 решений из исходных ответов и сохранённой разметки, сверяет результаты побайтово и проверяет, что все запросы обслуживали одна сборка и конфигурация.

## Сопоставление с исходной приёмкой

В сводке `observed_answerable_pairs` показано изменение на тех же 66 положительных вопросах. До повторной проверки полными были 30 ответов. После проверки складываются исправленные ответы из 36 и сохранившие полноту из 30. Разность долей в процентных пунктах рассчитывается с общим знаменателем 66. Вопрос о максимальной электрической мощности учитывается отдельно.

Для оценки доли по всем 135 положительным вопросам используется случайный отбор из 99 исходно полных ответов. Если полностью исправлены `f` из 36 и сохранили полноту `k` из 30, оценочное количество полных ответов равно `f + 99 × k / 30`. Поле `estimated_population_after` показывает эту оценку и точный двусторонний 95-процентный интервал. Для числа сохранивших полноту среди 99 инвертируются два хвоста гипергеометрического распределения по 2,5% при выборке без возвращения. К концам полученного интервала прибавляется известное число `f`. Это неопределённость от отбора 30 вопросов. Оставшиеся 69 вопросов не измерялись. Возможное расхождение оценщиков и изменчивость генерации при повторе в интервал не входят.
