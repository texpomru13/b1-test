# Проверка решения по ТЗ

Сервис принимает документ в фоновую обработку и отвечает на вопросы по выбранному документу. В таблице приведены критерии задания и проверки, которые можно повторить. На работающем стенде прошли 246 тестов. [Инструкция запуска](README.md)

## Проверка требований

| Что требует ТЗ | Что делает проект | Как проверить |
|---|---|---|
| Загрузка, статус фоновой задачи, список документов, вопрос по выбранному документу | FastAPI принимает PDF или DOCX, возвращает HTTP 202 и адрес задачи. Celery индексирует документ через Redis. Вопросы принимаются после публикации индекса | `sh eval/demo.sh` выполняет все четыре операции. [Маршруты и контракты](README.md#api) |
| Документ до 100 страниц, обработка в фоне | Число страниц проверяется в воркере. В DOCX страницы соответствуют результату конвертации LibreOffice, для скана возвращается причина отказа | На 100-страничном PDF проверяется успешная индексация, на 101-страничном — `PAGE_LIMIT_EXCEEDED`, на скане — `OCR_REQUIRED` |
| Одна коллекция Qdrant, метаданные, плотный и разреженный векторы | Точка содержит dense, BM25, `doc_id`, `doc_title`, `chunk_index`, `page_from`, `page_to`, `section`, `text`, `char_start`, `char_end`. Ключи фильтрации проиндексированы. Фильтр ограничивает поиск выбранным документом и опубликованной попыткой индексации | [Проверка реальной коллекции и восстановления](tests/integration/test_indexing_qdrant.py) |
| Обе ветви объединяются в Qdrant, затем работает отдельный реранкер | Один запрос с двумя ветвями формирует общий список. Метод RRF или DBSF, глубина обеих ветвей, модель реранкера, число кандидатов на его входе и размер итогового контекста задаются в окружении. При `debug=true` отдельный замер даёт раздельные счётчики. Из ответа видно, какие фрагменты попали в контекст и в цитаты | [Реальный гибридный поиск](tests/integration/test_retrieval_real.py) · [Диагностика ответа](eval/reports/submission/demo/10_debug.json) |
| LangChain для разбиения, эмбеддингов и вызовов LLM | Используются сплиттер LangChain, реализация `Embeddings` для документов и вопросов и чат-модели LangChain. На закреплённых весах Giga-480M проверены вызовы для документов и для поискового запроса | [Разбиение](app/ingestion/chunker.py) · [Адаптер эмбеддингов](services/local-models/app_lm/server.py) · [Провайдеры LLM](app/providers/factory.py) |
| Ответ с источниками, отказ при недостатке сведений, валидация, отсутствие истории | Координаты и страницы восстанавливает сервер. Контекст ограничен верхними результатами реранкера. Модель проверяет, закрывают ли цитаты вопрос. Pydantic валидирует ответ. Для каждого запроса формируется новый контекст | [Схема ответа](app/schemas/qa.py) · [Проверки через API](tests/integration/test_qa_live.py) |
| Конфигурация, временные ошибки, повторные попытки | При временном сбое LLM или Qdrant предусмотрены ограниченные повторы, для повторяемых 503 выдаётся `Retry-After`. Старый воркер не может записать состояние поверх новой попытки. Параметры, которые исключают обязательную верификацию, отклоняются при запуске | [Настройки](.env.example) · [Проверка сбоев](tests/integration/test_recovery_faults.py) · [Передача владения задачей](tests/integration/test_requeue_redis.py) |
| Инструкция запуска, архитектура, примеры с точным обозначением и без ответа, ограничения production | В начале README — запуск и демонстрация по двум реальным договорам. Демо печатает полные ответы и страницы, проверяет сумму с НДС, срок аренды, отказ и чужой документ, сохраняет JSON | [README](README.md) · [Демо](eval/demo.sh) |

## Пример с условием на другой странице

В договоре хостинга пользователь спрашивает, вправе ли заказчик перепродавать услуги, в том числе поддержку VDS через API. Пункт 6.10 на странице 5 начинается словами «Заказчик не имеет права». Подпункт 6.10.2 на этой же странице перечисляет перепродажу услуг. Подпункт 6.10.4 на странице 6 отдельно описывает перепродажу поддержки VDS, включая передачу через API. Сервис ответил, что оба действия запрещены, и приложил все три цитаты. Вводная фраза заняла второе место после реранжирования и вошла в контекст из восьми фрагментов. [Исходный договор](test_documents/03_VDS_Хостинг_Hoster.docx) · [Ответ и цитаты](eval/reports/submission/governing-clauses.json)

Связь между вводной фразой и действием проверена также на трёх коротких DOCX. Текст подпункта о передаче измерительных приборов подрядчику во всех трёх одинаков. В зависимости от вводного пункта API подтвердил разрешение, запрет или необходимость письменного согласия. На отдельном документе с одним перечислением действий сервис отказался делать вывод о праве. Координаты каждого доказательства относятся к исходному тексту. [Проверки связи между пунктами](tests/unit/test_governing_clauses.py)

## Приёмка на работающем стенде

- Использовались macOS Apple Silicon, Docker Compose, локальный Ollama и профиль `balanced`. Прошли **211 модульных и 35 интеграционных тестов** без пропусков. Интеграционные тесты работали с настоящими Redis, Qdrant, энкодером и реранкерами. Прошли Ruff, mypy и проверки всех трёх файлов фиксации зависимостей. На копии файлов для сдачи без локальных настроек `./run doctor --json` и `./run --dry-run` выбрали рабочий профиль.
- Сервис принял PDF на **100 страниц за 21 мс**. Через **223 секунды** задача завершилась и опубликовала 896 фрагментов. Задание для PDF на 101 страницу завершилось кодом `PAGE_LIMIT_EXCEEDED`, для сканированного договора без текстового слоя — `OCR_REQUIRED`.
- Сквозное демо выполнило 13 шагов. По п. 3.1.1 договора аренды получен ответ о 158 400 рублях с НДС, обе цитаты находятся на странице 5. Перефразированный вопрос о сроке аренды дал 11 месяцев от подписания передаточного акта. По отсутствующему обеспечительному платежу получен отказ. [Ответы демо](eval/reports/submission/demo)
- В трёх экземплярах приложения поочерёдно задавались недоступные адреса Redis, Qdrant и Ollama. Во всех трёх случаях проверка готовности показывала недоступную зависимость, а вопрос возвращал HTTP 503 с `retryable=true` и `Retry-After: 5`. При передаче задачи другому воркеру запоздалая ошибка первого сохранила владельца, статус и номер активной попытки. При сочетании сетевого повтора и невалидного JSON предел в четыре вызова LLM соблюдён. [Результаты индексации и проверок зависимостей](eval/reports/submission/runtime-checks.json)

## Результаты вопросов по документам

Профиль `balanced` прошёл **150 запросов через HTTP**. На 14 договорах проверены 93 вопроса с известным ответом, 40 вопросов без ответа и 17 обращений к чужому документу. Два экземпляра API обрабатывали запросы к фиксированной копии одной коллекции Qdrant. Энкодер, реранкер и LLM у них общие. Задержки в сырых ответах включают ожидание этих моделей.

| Критерий | Результат |
|---|---:|
| Ответ проходит схему Pydantic | 150/150 |
| Сервис дал ответ при наличии сведений | 80/93 |
| Корректный отказ при отсутствии сведений | 40/40 |
| Корректный отказ при вопросе к чужому документу | 17/17 |
| Цитата принадлежит запрошенному документу и совпадает с исходным текстом, координатами и страницей | 153/153 |
| В контекст попали все эталонные фрагменты | 90/93 |
| В выданном ответе цитаты покрывают все эталонные фрагменты | 64/80 |
| Все ожидаемые факты присутствуют, по локальной модели-судье | 50/93 |
| Ожидаемые факты, засчитанные моделью-судьёй | 180/248 |

Для покрытия каждого эталонного фрагмента требуется не менее 80% его символов. Полнота фактов оценивается отдельно от точности координат. Разметку вопросов составляли модели, цитаты проверены по извлечённому тексту. Судьёй выступал Qwen 27B. Часть вопросов использовалась при диагностике. Эти результаты характеризуют проверенный корпус. [Ответы API](eval/reports/submission/responses.jsonl) · [Детерминированные метрики](eval/reports/submission/metrics-all.json) · [Оценка полноты](eval/reports/submission/judge-all.json)

**Почему сервис иногда отказывает.** В 13 случаях ответ содержался в договоре, но сервис вернул отказ. В десяти из них все эталонные фрагменты уже находились в контексте. По журналам четыре отказа связаны с цитатой, которую не удалось найти дословно, три — с неподтверждёнными числами. Ещё в трёх случаях отказ вернула модель при генерации, в двух — верификатор отклонил содержание или полноту ответа. В одном случае сработала заключительная проверка количества предметов.

Например, при вопросе об ИНН, КПП и ОГРН ООО «Розница К-1» фрагмент с реквизитами оказался первым после реранжирования. Обе попытки остановила проверка числа, которого не было в выбранной моделью цитате. В вопросе о сроке годности модель использовала число 24, тогда как найденный пункт содержит условие «18 месяцев и более» и требование об остатке не менее одного года. [Причины отказов по журналам запросов](eval/reports/submission/refusal-analysis.json)

## Границы проверки

Для сканов нужен OCR. В договорах с нестандартной нумерацией или сложной вёрсткой сервис может не связать вводную фразу с подпунктом. При недостатке доказательств он возвращает отказ. Перед использованием с документами клиентов необходимы разграничение доступа, политика хранения, мониторинг очередей и согласованные резервные копии Redis, Qdrant и исходных файлов.

Полный запуск проверен на macOS с закэшированными весами. Для Windows/WSL2, NVIDIA, Docker Model Runner и облачных провайдеров проверялись конфигурации и программные контракты. Их следует отдельно испытывать в целевом окружении.
